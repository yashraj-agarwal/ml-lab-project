# CodeTrace AI

The academic report, presentation, ML handbook, team scripts, screenshots and reproducible experiments are in `evaluation_package/`. Start with `evaluation_package/README.md`; its research gaps and synthetic-data limitations are explicit.

CodeTrace AI is a small academic demonstration of static code analysis and supervised machine learning. It estimates whether Python source resembles examples labeled `human` or `ai`. Its output is an uncertain model estimate, not proof of authorship.

## Implementation plan

1. Extract Python lexical, AST, and structural features without executing submitted code.
2. Train three models on a labeled CSV, select by validation F1, and keep a problem-grouped held-out test split for reported metrics.
3. Serve the saved pipeline and actual evaluation results through FastAPI.
4. Present code analysis, evaluation, and project limitations in a small React app.

## Requirements

- Python 3.10 or newer
- Node.js 22 or newer and npm

## Install, train, and run

From the repository root, in PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
python backend\train.py
uvicorn backend.main:app --reload
```

In a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the Vite URL printed in the frontend terminal (usually `http://localhost:5173`). The frontend calls the API at `http://localhost:8000`.

On another platform, use `python3 -m venv .venv`, activate the environment using that platform's command, and start the API with `uvicorn backend.main:app --reload`.

## Dataset

`data/samples.csv` is a synthetic demonstration dataset generated by `python backend/make_demo_data.py`. It has `code`, `label`, and `problem_id` columns. Labels must be `human` or `ai`. The loader removes missing, blank, invalid-label, and duplicate-code rows. It reports class distribution and requires at least five distinct problem groups. Group-based train, validation, and test splits keep all samples with the same `problem_id` together to reduce problem-level leakage.

The bundled examples are intentionally small and repetitive so the workflow can be run locally. Their metrics are a software demonstration only, not evidence of real-world detection performance. Replace the CSV with diverse, consented human samples and carefully matched AI examples before drawing research conclusions. Keep `problem_id` stable for submissions from the same assignment/problem. Retrain after replacing the data.

Train with a custom CSV path:

```powershell
python backend\train.py path\to\your_dataset.csv
```

Training writes `models/codetrace.joblib` (the selected model pipeline) and `models/metrics.json` (validation selection, held-out test metrics, confusion matrix, and feature importances). These generated artifacts are omitted from version control and can be reproduced by training.

## Models and features

- **Logistic Regression** learns a weighted linear boundary and estimates class probabilities.
- **Decision Tree** classifies through successive feature-based decisions.
- **Random Forest** averages many decision trees to reduce dependence on a single tree.
- **Feature engineering** combines TF-IDF token and token-pair patterns with code length, line and token statistics, identifier style, comment density, function/loop/condition/class counts, and AST node/nesting/docstring features. Numeric features are standardized. Python's built-in tokenizer and AST parser perform static inspection only.
- **Evaluation** reports accuracy (fraction correct), precision (fraction of AI predictions that are AI-labeled), recall (fraction of AI-labeled samples found), F1 (harmonic mean of precision and recall), and a confusion matrix. The candidate is selected on validation F1; the comparison table is reported on the held-out test split.

The dataset loader requires both labels and enough problem groups for the grouped splits. Metrics can vary with the dataset. A high score on a small or synthetic dataset does not establish authorship or generalize to different people, tasks, languages, or model versions.

## API

Regression checks: `python -m unittest backend.test_pipeline -v`. Model schema 2 uses comment-token count divided by code-line count, rejects invalid Python at the API, rejects conflicting dataset labels, and records training library versions. Retrain artifacts when feature definitions change. The frontend now uses Tailwind CSS 4.

- `GET /api/health` checks API and artifact readiness.
- `GET /api/models` and `GET /api/metrics` return evaluation results.
- `POST /api/analyze` accepts `{ "code": "...", "language": "python" }` and returns a saved-model prediction, confidence, and extracted signals.

Only Python is supported. Requests are limited to 20,000 characters. Submitted code is never executed.
