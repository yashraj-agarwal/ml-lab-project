# Live Experiments and Demonstrations

Run `python evaluation_package/05_Experiments/run_experiments.py` then `python evaluation_package/05_Experiments/make_charts.py` from the project root. Install optional plotting dependencies with `python -m pip install -r evaluation_package/05_Experiments/requirements.txt`.

The runner loads the saved model for input edits and independently fits experimental Logistic Regression configurations. It does not overwrite the deployed model. Configuration metrics use the existing validation partition, not repeated test-set tuning. All output scores below were generated by the runner; percentages must not be interpreted as real-world reliability.

## Experiments 1–4 and 8: paired source changes

Original/modified inputs, changed numeric features, class predictions and probabilities are stored in paired_input_comparisons.csv. Every feature dictionary is also present in experiment_results.csv. For finite integer lists, renaming, adding comments, compacting spaces and replacing the explicit filtering loop by a comprehension preserve the baseline behavior. The factorial probe is a different unlabeled task; it tests whether inference runs, not whether authorship is correctly identified.

## Experiments 5–7: configuration, ablation and threshold

Numeric style group: comment ratio, average line length, average identifier length, snake/camel ratios and blank-line ratio. Structural group: function, loop, conditional, class, exception, AST-node, nesting and docstring counts. Remaining size/token features are retained; these ablations are not a disjoint decomposition of every possible style signal.

C=1 with all features is the reference configuration. Smaller C gives stronger regularization and changes probability despite unchanged validation classes. All ablations have perfect validation metrics on this artificial fixture, so they cannot establish which groups are most useful on real data. Thresholds 0.4–0.7 leave validation precision and recall unchanged because no scores cross those cutoffs. For the recorded structural-refactor probe, its probability near 0.5442 would predict AI at 0.5 and human at 0.6 without refitting; the class rule changes while the score stays fixed. This is a threshold illustration on one fixed score, not a newly measured validation result.

## Practical demonstration sequence

1. Start the local backend and frontend using the repository README.
2. Paste the baseline from paired_input_comparisons.csv and record its estimate.
3. Paste each paired modification and inspect the returned raw features and score.
4. Open the generated CSV for C, ablation and validation-threshold comparisons.
5. Explain any unchanged class as a legitimate outcome. Do not edit the UI prediction or search until a desired result appears.
6. Show the factorial score and explicitly say its origin is unlabeled.

Reproduce experiments after every feature or model change; report schema-2 values, not the older schema-1 probabilities.
